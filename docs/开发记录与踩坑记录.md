## 三、踩坑记录（重点）

### A. 环境与工具链

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 1 | PowerShell 不支持 `&&` | 命令中断 | 用 `;` 分隔 |
| 2 | `python -c` 内联引号冲突 | 语法错乱 | 一律写成 `.py` 文件执行 |
| 3 | 本机 curl 直连 `*.workers.dev` 超时 | DNS 被污染（解析到 157.240.3.50 等无关 IP） | 云端验证一律走**浏览器内 fetch**（bu.js） |
| 4 | curl 到 api.github.com / raw 间歇 Connection reset | 拉取失败 | 加 `--ssl-no-revoke`；或走浏览器 |
| 5 | 本机没装 git / gh | 命令找不到 | winget 装 Git；gh 用官方 zip 解压到 `C:\Users\Administrator\gh` |
| 6 | git push 弹出凭据窗 / 卡住 | 无凭据缓存 | 用 gh token 直连：`git push "https://x-access-token:<token>@github.com/...git" main` |
| 7 | wrangler 全局装到 sandbox 目录 | 入口不在 PATH | 用完整路径 + `node` 运行：`node ...\wrangler\bin\wrangler.js` |
| 8 | wrangler 认证变量名 | 认不到 token | 用 `$env:CLOUDFLARE_API_TOKEN`（不是 WRANGLER_API_TOKEN） |
| 9 | 图片 Read 限 5MiB / PIL 未装 | 读不了角色卡大图 | System.Drawing 压缩后再 Read |
| 10 | workers.dev 子域名未注册 | 首次 deploy 报错 | 浏览器接管完成 onboarding，子域名=1020803065（API 改名被 409 拒） |

### B. 敏感文件事故

- **事故**：`git add -A` 误把 `cf_token.txt`、`iseria_admin_password.txt`、`worker/.wrangler/` 塞进暂存区，用户并行推送卡住。
- **处置**：确认远端 HEAD 仍在干净 commit → 删除三个敏感项 + 补 `.gitignore` → `git reset --mixed` 重加重新推送 → 线上验证仓库根目录无敏感文件。
- **教训**：任何 token/密码文件不进仓库；敏感信息只存桌面本地。

### C. 内容包与宿主脚本设计坑

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 11 | `replaceScriptButtons` 会覆盖同卡其他脚本按钮 | 伊瑟利亚自带按钮消失 | 改 `appendInexistentScriptButtons`（只追加不覆盖；两者都只作用于当前脚本，安全） |
| 12 | `window.confirm` 在酒馆脚本 iframe 被静默抑制 | 点按钮无反应（console 报 "dialog was suppressed"） | 弃用 confirm，改为**遮罩内嵌免责声明页** |
| 13 | **遮罩挂错 document**（本 bug 的根因） | 脚本 iframe 是隐藏的，`document.body.appendChild` 把遮罩挂进隐藏 iframe → 全屏遮罩"创建了但看不见" | 遮罩/iframe 一律挂 `window.parent.document`（父页面=酒馆网页）；非 iframe 环境回退自身 |
| 14 | **跨窗口 `location.replace` 被静默忽略** | 从脚本 iframe 上下文导航兄弟 iframe 到工坊，不报错也不跳转 | 改为**重建 iframe + 设置 `src` 属性**（纯 DOM 操作） |
| 15 | 消息监听挂错窗口 | 工坊 iframe 挂在父页面后，`parent.postMessage` 发往父窗口 | 监听挂 `window.parent`（MSG_TARGET），来源校验 + 只挂一次标记 |
| 16 | 酒馆助手 UI 保存脚本报 `toSorted is not a function` | 点确认保存崩（酒馆助手自身 bug，把非数组当数组排） | 绕开 UI：直接改角色卡 JSON 的 `scripts` 数组 |
| 17 | 宿主脚本 import 格式 | 裸 URL 装不进去 | 必须是 `"import 'https://…'"` 字符串（带 import 关键字） |
| 18 | jsDelivr URL 用 `/npm/` | 404 加载失败 | GitHub 仓库用 `/gh/用户名/仓库@分支/路径` |
| 19 | **jsDelivr `@main` 缓存不一致** | 同 URL 各边缘节点返回不同版本（cdn 新 / testingcf·fastly·gcore 旧）；大陆节点命中旧缓存 | 用 **commit hash** 引用（`@8dcd718`）——不可变、无缓存歧义；更新时换新 hash |
| 20 | 用户把代码全文粘贴进 UI | 脚本内容带引号/被当 JSON 解析（Toolbar.vue 报错） | 只填一行 import URL；按钮由脚本自动注册，勿手动加同名按钮 |
| 21 | 同名按钮残留 | 旧空壳按钮（无效脚本）点击无反应 | 删除无效脚本，只留一个正确来源 |

### D. 云端/前端坑

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 22 | workers.dev 在中国大陆网络**时好时坏** | 用户浏览器打开工坊前端偶发"响应超时" | 方案 A：多试/稍后重试；方案 B（推荐）：前端页面迁到 GitHub Pages，Worker 只做 API |
| 23 | 前端页面改动后未重建 | 部署的仍是旧 HTML | 改 `worker/public/*.html` 后必须重跑 `Temp/generate_html_module.py` 重建 `src/public_html.js` |
| 24 | KV 数据误伤 | 同名待审防刷、打回后待审清零 | 后端校验红线：tags 白名单、version x.y.z、世界书 ≤200 条/单条 ≤5 万字、正则 ≤50、投稿 ≤2MB |
| 25 | **安装 404：downloadUrl 用了相对路径** | 前端页面与 Worker 同源时相对路径可行，但宿主脚本在**酒馆页面**（跨源）fetch 相对路径 → 请求发到酒馆站点 → HTTP 404 | downloadUrl 一律拼**完整 URL**：`location.origin + '/api/files/...'`（前端页面 origin = Worker origin） |

## 六、安装到酒馆的正确姿势

1. 角色卡 JSON 的 `extensions.tavern_helper.scripts` 数组加一条字符串（**带 import 关键字**，路径用 commit hash）：

```json
"import 'https://cdn.jsdelivr.net/gh/ayunsama/iseria-workshop@8dcd718/host-script/index.js'"
```

2. 保存角色卡 → 重新加载。
3. 点「伊瑟利亚创意工坊」按钮 → 全屏遮罩 → 免责声明（首次）→ 工坊页面。
4. 不要用酒馆助手 UI 粘贴代码全文；按钮不要手动添加（脚本自动注册）。
